# GPT6Astra Game Development Skills

**用于提升 GPT6Astra 游戏开发能力的通用 Agent Skills。**

General-purpose skills for improving GPT6Astra's game development workflow and output quality.

本仓库包含五份可独立使用、也可组合执行的技能文档，覆盖 **建模与动画、配色与美术、粒子与特效、参考素材研究，以及主 agent / subagents 的 critic 迭代**。它们将视觉目标拆成可执行步骤，用实际画面、玩法和运行证据约束交付，帮助 GPT6Astra 更深入地完成游戏开发与打磨。

这些方法来自一个奥日风格游戏的开发实践，已提炼为可迁移的工作流程。用于其他游戏时，应重新建立目标作品的参考、风格与验收条件。

## 五个 skills

| Skill | 适用问题 | 核心方法 |
| --- | --- | --- |
| [astra-game-organic-modeling](skills/astra-game-organic-modeling/SKILL.md) | 肢体像简单几何体拼装，关节粗糙，动作僵硬 | 连续曲面、合理分配 triangles、关节变形、动作分层、真实表面接触检查 |
| [astra-game-art-direction](skills/astra-game-art-direction/SKILL.md) | 蓝绿色惯性、配色偏淡、亮暗层次不足、风格不符 | 参考驱动的分区配色 recipe、明暗分组、实际承光面、最终渲染对照 |
| [astra-game-vfx](skills/astra-game-vfx/SKILL.md) | 粒子像均匀星点或彩纸，攻击反馈弱，雾与景深失真 | 分层特效、事件时序、Three.js 实现路径、透明合成、空气感与镜头反馈 |
| [astra-game-reference-study](skills/astra-game-reference-study/SKILL.md) | 参考不足、认错角色、技能形态混淆、实现“味道不对” | 核实素材身份、查看视频、局部裁图、阶段分析，将观察转成实现约束 |
| [astra-game-critic-loop](skills/astra-game-critic-loop/SKILL.md) | 子代理声称完成，但实际效果仍未达标 | 主代理定义目标并复核证据，定向返修，停滞时重新诊断或交给新代理 |

每份 SKILL.md 都包含适用范围、执行方法、验收或退回条件，以及从实际开发中提炼的经验。可以按当前问题选择一份，不必每次加载全部文档。

## 快速使用

### 直接在项目中使用

将本仓库克隆或下载到本地，然后让 agent 阅读所需文档，并提供当前游戏、参考素材与目标。例如：

~~~text
请阅读 skills/astra-game-organic-modeling/SKILL.md，并按其中的方法执行。

基于当前游戏改善主角的腿部模型、奔跑与下落动作。
先检查已有参考和当前输出，明确造型、时序与接触分别有哪些问题。
保留现有跳跃高度、移动速度和碰撞规则。
交付实际改动、同阶段前后画面对照、相关行为验证和剩余差异。
~~~

路径相对于本仓库；在其他工作目录中使用时，提供对应文件的完整路径。

### 安装到支持 Skills 的 agent 工具

把 skills/ 下需要的完整技能目录放入所用工具支持的技能目录，保留 SKILL.md 的文件名与目录结构。随后按该工具的方式加载或调用 skill。

这些文档采用 YAML frontmatter + Markdown 的格式，不依赖本机绝对路径。实际发现、调用和多代理能力由宿主工具提供；使用这些文件不会自动切换模型。需要针对 GPT6Astra 执行时，在宿主中选择相应模型。

## 推荐组合流程

先用参考研究建立依据，再由主 agent 定义目标和分工，按问题调用建模、美术或特效 skill。每轮实现之后返回主 critic 验收。

~~~mermaid
flowchart TD
    R[核实参考并建立可观察要求] --> C[主 agent 定义目标与验收条件]
    C --> M[建模与动作]
    C --> A[配色与美术]
    C --> V[粒子与特效]
    M --> E[查看实际画面与玩法证据]
    A --> E
    V --> E
    E --> J{是否达到约定目标}
    J -->|未达到| F[具体 feedback 与定向返修]
    F --> C
    J -->|达到| D[统一版本验收与交付]
~~~

适合完整打磨任务的提示词：

~~~text
请使用本仓库的参考研究和 critic 迭代 skill，打磨当前游戏。

1. 先阅读已有代码、素材与当前画面，核实目标角色、动作和场景。
2. 主 agent 写清目标状态、验收方法和需要保持的现有行为。
3. 按实际问题分配建模、美术和特效子任务，明确文件写入边界。
4. subagent 提交候选实现、对应版本、真实画面与验证结果。
5. 主 agent 必须查看证据。未达标时指出具体差距、修正方向和复验条件。
6. 同一问题反复停滞时，重新诊断根因，必要时交给新的 subagent。
7. 达到目标后，用同一最终产物完成相关联合验收，说明仍存在的差异。

不要用代码量、测试数量或子代理的完成声明代替体验验收。
~~~

普通的小修复可以只使用对应专项 skill；多代理流程适合需要持续打磨或跨模块协作的任务。

## 关键设计原则

### 建模和动作分开诊断

更多三角形应服务于轮廓、曲率和关节变形。动作还需要正确的时序、重心、IK、接触与过渡。保留项目明确选择的低模或机械风格，不为了“精细”统一改成平滑有机曲面。

### 配色由参考与场景职责决定

按前景、中景、空气、光核和可玩路线建立色彩关系。暖色任务不能被全局青雾重新染回默认色系；参考本来是青绿色时，也不应机械禁用青绿。以最终渲染评价结果，区分屏幕取样与材质参数。

### 特效需要形状、时间和因果

将预备、释放、飞行、命中与余辉分开设计。环境粒子、雾、景深承担不同职责；同时检查遮挡、透明细线、暂停与重复触发。Three.js 的具体实现建议集中在特效 skill 中。

### 让参考成为开发条件

实际查看目标视频，核实角色与技能，再做全画面和局部裁图分析。将观察到的比例、动作、色彩或镜头变化映射到具体实现与验收；区分已观察事实、技术推断与未知参数。

### 严格 critic 负责可验证的反馈

主 agent 明确指出差在哪里、为什么影响目标、下一轮怎样修、怎样复验。已通过的部分保持稳定；候选实现与最终交付分开标识，相关证据绑定实际产物版本。

## 实践来源与适用边界

这组 skills 提炼自一次主 agent 与多个 subagent 累计约 10 小时的奥日风格游戏迭代，涉及单文件 HTML、程序化建模、角色动作、远程攻击、借光弹射、场景美术、雾与景深等问题。

- [案例试玩](https://luma-forest-task-v6.steelydrive1.chatgpt.site)
- [带声音的试玩视频](https://luma-forest-task-v6.steelydrive1.chatgpt.site/watch.html)

这里迁移的是开发与评审方法。新的游戏需要自己的参考、设备预算和验收条件；原案例的色值、面数、镜头参数与投入时长均不是通用要求。

文档面向 GPT6Astra 的开发工作流设计。当前经验来自案例实践，尚未进行跨模型或多游戏基准评测。使用其他模型或引擎时，可以保留参考、验收与迭代方法，并调整具体实现方式。
