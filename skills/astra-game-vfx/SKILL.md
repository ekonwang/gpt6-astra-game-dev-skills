# 分层特效与空气感

为 GPT-6 Astra 提供从可见效果到实现与验收的约束。奥日案例中的廉价感主要表现为均匀亮点、等宽光幕、同时爆开的碎片和缺失的技能镜头；这些是诊断样例，不是所有游戏都应使用柔雾与辉光。

**先定义特效告诉玩家什么，再确定形状、时间、颜色和空间。增加粒子数量不等于增加表现力。**

## 1. 拆出效果的视觉与玩法职责

对照已核实的片段，按事件记录预备、释放、飞行、接触、余辉和恢复。不要只截最亮的一帧。

| 层 | 视觉职责 | 常见实现选择 |
| --- | --- | --- |
| 核心 | 短促、可定位的能量或命中中心 | 小型软片、局部几何或 shader |
| 主形状 | 表达方向、范围、速度与技能身份 | 带状网格、弧线、矛尖、锥形或局部环 |
| 尾迹 | 连接运动历史，显示速度与转向 | 按时间或距离采样的 ribbon / segment |
| 碎屑 | 表达冲量、材质破碎或能量散逸 | 定向实例片或少量点 |
| 余辉 / 烟尘 | 收束事件、交代环境响应 | 低对比软片、渐散雾团 |
| 环境空气 | 体现局部湿度、光隙和空间深度 | 分层雾、局部尘埃、稀疏漂浮物 |
| 镜头 / 声音 | 强调蓄力、释放与触感 | 事件驱动的缩放、轻震与同步音效 |

选择参考真正需要的层；低成本的小效果不必全用。为每层写清发射位置、方向、尺寸、寿命、速度、亮度曲线、遮挡关系和时钟归属。不要把所有层赋同一颜色、大小、速度与寿命。

## 2. 建立可实际运行的 Three.js 路径

沿用项目的引擎与版本。以下针对 WebGLRenderer；使用其他渲染器或引擎时映射到其支持的方式，不混用 API。

- 点状尘埃或小光点：用 [Points](https://threejs.org/docs/pages/Points.html) 与 BufferGeometry 共享缓冲。
- 需要朝向、长宽比或立体轮廓的碎屑：用 [InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html) 或实例化面片，减少逐粒子绘制调用。修改实例矩阵或颜色后更新对应缓冲标记。
- 需要非线性淡入淡出、软边、噪声或沿速度拉伸：用 [ShaderMaterial](https://threejs.org/docs/pages/ShaderMaterial.html) 或项目已有等价材质。
- 尾迹需要连续运动历史，使用带宽度与透明度变化的条带；角色传送、重生和池复用时清空历史，防止跨图拉线。
- 单文件或离线交付时，纹理可程序生成或嵌入许可允许的资源；不能悄悄增加 CDN 或外部素材依赖。

实现最少应包含：可渲染对象与材质、参数更新、事件发射、回收机制，以及真实游戏循环中的接入。仅写效果参数表、空类或独立截图不算实现完成。

### 粒子与事件数据

根据效果选择必要字段：

~~~text
事件：id / kind / tick / origin / finalDirection / impactNormal / intensity
粒子：active / birthTime / lifetime / seed / position / velocity / size / rotation
曲线：size(age) / opacity(age) / color(age) / stretch(speed)
资源：poolCapacity / overflowPolicy / geometry / material
~~~

- 池容量和溢出策略明确；优先回收已结束或低优先级环境效果，不能让视觉池溢出阻止真实伤害结算。
- 复用时重置所有历史、alpha、可见性与随机状态。避免每帧创建几何、材质和临时数组。
- 随机分布受主方向、材质与局部区域约束。背景装饰使用独立随机序列，不因减少粒子改变关卡或敌人生成。
- 多个实例共享材质时，不能用一个全局 opacity 控制本应各自衰减的效果；使用实例属性、uniform 分组或适当独立材质。

## 3. 让释放、飞行和命中有因果关系

主角姿态、武器、弹体、箭头、镜头和声音消费同一事件或同源数据。先更新有效姿态与变换，再取得当前帧的发射位置和最终方向。

- 伤害由既定战斗 / 碰撞逻辑决定，命中特效订阅实际命中。不要在发射瞬间播放远端命中并扣血，除非玩法本来就是瞬发。
- 发射微闪短、集中；飞行尾迹窄、连续；命中碎屑按入射方向与接触法线展开；余辉更慢更弱。节奏按参考调校，不套统一“爆炸”。
- 同帧最后一次转向与松键时，残光、弹体和镜头取最终方向，不取上一渲染帧缓存。
- 在慢动作、暂停、失焦、重启和中断时有明确策略。世界特效通常随世界时间；镜头需要不同速度时用明确的视觉时钟，但暂停仍按产品规则冻结。
- 不用独立墙钟让暂停后的碎屑突然跳完寿命，不让慢镜中的飞箭无依据地停住。

奥日案例曾因弓与弹体共享淡出材质导致在飞箭一起消失，也曾因复用错误角度分布让松弦碎屑变成实体折扇。必须检查连续播放和资源复用，不能只检查对象存在。

## 4. 环境粒子、雾、景深分别处理

“朦胧”至少可能来自三种因素，先判断参考需要哪一种：

| 因素 | 作用 | 错误替代 |
| --- | --- | --- |
| 空气透视 / 距离雾 | 随空间距离改变对比与色彩 | 用一层白色覆盖整幕 |
| 局部漂雾 / 光束 | 显示低频流动、遮挡和局部透光 | 堆满等亮萤火点或等宽光柱 |
| 景深 | 焦面外细节失焦 | 把整个画面统一模糊 |

- 环境粒子集中于光隙、水边、火源等有依据的位置，保留稀疏区与负空间。尺寸、亮度和距离有主次，不把全屏变成星空。
- 雾层有空隙、缓慢低频变化和前后关系，玩法焦面覆盖受控。少量远景软化往往比增加大量近景粒子更有效。
- 光束具备局部亮核、沿路径衰减和遮挡断续；检查实体是否承光，避免“光在那里，场景却没有反应”。
- 只有参考或美术目标需要时才加入 DOF。依据相机空间深度与焦面实现，并在镜头缩放、resize 和不同 DPR 下验证。

Three.js 可通过 [DepthTexture](https://threejs.org/docs/pages/DepthTexture.html) 获取深度。深度图不自动代表所有透明特效；透明物体的写深度策略必须单独检查。

## 5. 处理透明合成与细线保护

软边粒子常从 transparent=true、depthTest=true、depthWrite=false 起步，再按效果调整；这不是所有透明物体的统一配置。烟雾通常需要透明度混合，发光层可考虑加法混合，不能让每层都把背景加成白色。

需要软化烟雾与地面、墙面的交界时，可用场景与粒子的视空间深度差渐隐，并按相机投影正确还原深度。软边贴图本身不会消除与实体相交的硬切线。

[Three.js 透明度说明](https://threejs.org/manual/pages/transparency.html) 提醒了对象排序与内部几何排序的局限。相交面片或实例的排序问题不能仅靠关闭深度写入解决；根据成本使用深度分层、重排、适当裁切或其他适用方法。

- 世界中的火花、烟尘应保持合理遮挡；只有明确作为玩法提示的标记才考虑覆盖显示。
- DOF 可采用深度 / 对象保护 mask，或在失焦背景之后以正确遮挡关系合成清晰玩法层。
- 使用保护 mask 时，既检查当前像素，也检查模糊邻域的采样来源，防止受保护的细弓弦、箭尾被复制成重影。
- 低分辨率 mask 可能漏掉细线；先提高有效采样覆盖或分辨率，再测高 DPR、低画质与透明度边缘。
- 不能用主角周围一个大圆形清晰区掩盖所有对象保护问题，也不能为清晰把本应被墙挡住的弹体显示到墙前。
- 多 pass 渲染结束后恢复相机层、render target、背景、清屏与统计状态，避免截图或水反射污染下一帧。

## 6. 将镜头效果与真实演示一起验收

参考有蓄力推近、释放拉远时，建立“进入—保持—释放—恢复”曲线。正常镜头跟随、技能偏移与缩放应可组合；连续触发从当前状态衔接，不硬跳回起点。

通过静态环境标记的屏幕尺度确认 zoom 确实发生。只改变 camera 参数或角色大小，不能证明整个场景产生了预期效果。检查各朝向、宽高比、主角 / 目标 / 指示箭头安全范围与重生恢复。

自动演示必须经过真实可见的预备和瞄准阶段。若同一更新步开始并释放技能，箭头即使存在也没有展示帧。可以为自动演示安排可读的保持时间，不能给玩家输入强加相同延迟。

## 验收与退回

提交完整事件短片、关键阶段接触表、实际游戏背景上的近景，以及必要的开关对照。重点检查：

- 亮背景与暗背景都能读懂主形状、方向和作用点。
- 暂停、取消、重复触发、池复用与场景重置无残影或错向。
- 画面没有均匀彩纸、折扇碎片、贯穿灯帘或透明细线重影。
- 技能不仅在测试入口可见，也在玩家操作与最终自动演示中出现。
- 性能按实际帧测量，计入透明 overdraw、反射、mask、bloom 和后处理；不只报粒子数或主场景 draw calls。

需要有声试玩视频时，检查导出文件有真实可解码的音轨，且发射 / 命中与画面同步；播放页允许用户启用声音。

反馈示例：“命中白核的时序已通过。释放碎屑仍像一把等长扇子，只修改该层的方向簇、长短与寿命；保留弹道和伤害，补交明暗背景连续播放与三次连发后的回收检查。”

交付记录实际版本、目标设备、性能边界和剩余差异。测试数量与特效层数不作为美术完成度的替代。
